# CardDemo TypeScript migration (`ts/`)

TypeScript port of the AWS CardDemo COBOL application. This package is the
**foundation** every later migration session builds on: copybook record
layouts, COBOL data codecs, a VSAM-equivalent keyed store with COBOL and CICS
file APIs, seed-data loading, sequential file helpers, and the `CSUTLDTC` /
`COBSWAIT` utility ports.

```bash
source ~/.nvm/nvm.sh     # Devin VMs: node may only be on PATH after this
cd ts && npm ci
npm test                 # vitest
npm run lint             # eslint
npm run typecheck        # tsc --noEmit (strict)
npm run check            # all three
```

## Layout

```
ts/
  src/
    index.ts                 public API (re-exports everything below)
    common/
      codecs/                PIC parsing + byte codecs
        pic.ts               PICTURE parser, storage lengths per USAGE
        decimal.ts           decimal.js clone (precision 40, HALF_UP) + MOVE truncation
        zoned.ts             DISPLAY numeric, trailing overpunch sign (ASCII {A-I }J-R, EBCDIC Cx/Dx/Fx)
        packed.ts            COMP-3 / PACKED-DECIMAL
        binary.ts            COMP / COMP-5 / BINARY (big-endian, two's complement)
        edited.ts            numeric-edited PICs (Z * , . B 0 / + - $ CR DB)
        ebcdic.ts            CP037 <-> Latin-1 (table generated by tools/gen-cp037.py)
        charset.ts           ascii/ebcdic text helpers, SPACES/LOW-VALUES/...
      record/layout.ts       declarative record layouts: parse / serialize / metadata
      copybooks/             one layout per app/cpy copybook (see table below)
      vsam/
        dataset.ts           VsamDataset: KSDS (prime + unique/non-unique AIX) and ESDS storage
        catalog.ts           VsamCatalog: clusters by DSN / DD name / CICS file name
        cobol-file.ts        IndexedFile / EsdsFile: OPEN/READ/WRITE/REWRITE/DELETE/START + FILE STATUS
        cics-file.ts         CicsFileControl: EXEC CICS READ/WRITE/REWRITE/DELETE/STARTBR/READNEXT/READPREV/RESETBR/ENDBR + RESP
        status.ts            FileStatus codes, Resp codes
      io/sequential.ts       LINE SEQUENTIAL and fixed-length sequential files (SequentialFile + helpers)
      seed/index.ts          cluster definitions from app/jcl + loader for app/data
      utils/                 ceedays.ts (CEEDAYS), csutldtc.ts (CSUTLDTC), cobswait.ts (COBSWAIT)
    batch/<program>/         <- batch sessions: one directory per COBOL program (e.g. batch/cbtrn02c/)
    online/<area>/           <- online session: CICS framework + programs (e.g. online/framework/, online/account/)
  test/                      vitest suites; test/golden/ = GnuCOBOL-generated expected output
  tools/                     generators (CP037 table, CSLKPCDY lookups, GnuCOBOL golden files)
```

Conventions for later sessions: keep program-specific code under
`src/batch/<program>/` or `src/online/<area>/`, import shared pieces from
`src/common/...` (or `src/index.ts`), put tests in `test/batch/<program>/...`
or `test/online/...`, and add a LIMITATIONS section to your module README.

## Record layouts

```ts
import { AccountRecordLayout } from './src/common/copybooks/index.js';

const acct = AccountRecordLayout.parse(line);        // typed object; numerics are Decimal
acct.acctCurrBal = acct.acctCurrBal.plus('10.25');
const bytes = AccountRecordLayout.serialize(acct);   // Buffer, 300 bytes
AccountRecordLayout.range('ACCT-ID');                // { offset: 0, length: 11 }
AccountRecordLayout.serialize({ acctId: 7 });        // missing fields -> VALUE / INITIALIZE defaults
```

- Numeric items (`num`) are `Decimal` (decimal.js). Native JS numbers are only
  accepted as input when they are safe integers; money must be `Decimal` or a string.
- Alphanumeric and numeric-edited items are strings. A numeric-edited field also
  accepts a number/Decimal/plain numeric string, which is edited per its PICTURE.
- `parse(buf, { charset: 'ebcdic' })` for CP037 data. `views: true | [...]`
  decodes REDEFINES views (otherwise they are omitted); a view present in the
  input object of `serialize` overwrites the storage it redefines.
- Define new layouts with `defineRecord`, `alnum`, `num(name, pic, { usage })`,
  `edited`, `group`, `occurs`, `redefines`.

## VSAM store and seed data

```ts
import { loadSeedCatalog, CARDDEMO_CICS_FILES } from './src/common/seed/index.js';
import { IndexedFile, CicsFileControl, Resp } from './src/common/vsam/index.js';

const { catalog } = loadSeedCatalog();               // all clusters, loaded from app/data
// const { catalog } = loadSeedCatalog({ transactFromDailytran: true }); // TRANSACT from dailytran.txt

// Batch (COBOL file I/O): names resolve by DD name, CICS name or DSN.
const acct = new IndexedFile(catalog, 'ACCTFILE', { access: 'RANDOM' });
// Pass `alternateKeys` with the ALTERNATE RECORD KEYs the SELECT declares ([] for none):
// only those report status 02 on WRITE/REWRITE; other cluster AIXs (e.g. TRANAIX) give 00.
// new IndexedFile(catalog, 'TRANFILE', { access: 'RANDOM', alternateKeys: [] });
acct.open('I-O');                                   // '00' | '35' ...
const { status, record } = acct.read('00000000001');// '00' | '23'
acct.rewrite(record!);                              // also acct.status

// Online (EXEC CICS): one CicsFileControl per task.
const cics = new CicsFileControl(catalog, CARDDEMO_CICS_FILES);
const r = cics.read({ file: 'CXACAIX', ridfld: '00000000001' }); // Resp.NORMAL | DUPKEY | NOTFND
cics.startbr({ file: 'CARDDAT', ridfld: '0'.repeat(16) });
cics.readnext({ file: 'CARDDAT' });                 // ENDFILE at end
```

CICS files: ACCTDAT, CARDDAT, CARDAIX (path), CCXREF, CXACAIX (path), CUSTDAT,
TRANSACT, USRSEC. `readDailyTransactions()` and `readExportFile()` return the
DALYTRAN and EBCDIC export records. Data in the store is ASCII.

Statuses implemented — COBOL: 00, 02, 05, 10, 21, 22, 23, 35, 37, 41, 42, 43,
46, 47, 48, 49. CICS RESP: NORMAL, NOTFND, DUPREC, DUPKEY, INVREQ, NOTOPEN,
ENDFILE, LENGERR, FILENOTFOUND, DISABLED. CICS browse semantics: STARTBR GTEQ
(default) / EQUAL / GENERIC, high-values RIDFLD + READPREV = last record,
READPREV straight after an inexact STARTBR = NOTFND, direction change returns
the same record again, READNEXT with a changed RIDFLD repositions.

Sequential files: `SequentialFile(path, { organization: 'LINE' | 'FIXED', recordLength })`
with OPEN/READ/WRITE/CLOSE statuses, plus `readLineRecords`, `readFixedRecords`,
`writeLineRecords`, `writeFixedRecords`.

## Utilities

- `csutldtc(date, format)` -> `{ result (80 chars), returnCode, severity, msgNo, message, lillian }`.
- `ceedays(date, picture)` -> `{ lillian, feedback }` (Lillian day 1 = 1582-10-15).
- `cobswait(sysin, sleep?)` waits `centiseconds * 10` ms; `parseWaitParm` mirrors MOVE X(8) TO 9(8) COMP.

## Testing

- Every copybook with seed data is round-tripped byte-for-byte against every
  seed record (ASCII files, the CP037 USRSEC file and all 500 CP037 export records).
- `test/golden/` holds output of reference COBOL run under GnuCOBOL 3.1
  (`tools/gen-golden.sh`, needs `cobc`): numeric-edited/zoned MOVE results and an
  indexed-file FILE STATUS sequence; `test/golden.test.ts` compares against them.

## LIMITATIONS

- **CEEDAYS** is a re-implementation (LE is not available under GnuCOBOL).
  Supported picture tokens: YYYY, YY, MM, DD, DDD, MMM/MMMMMMMMMM, literal
  separators; eras and other tokens return "Bad Pic String". Expected values in
  tests come from the LE documentation and tracing CSUTLDTC, not a mainframe run.
  The YY century window defaults to current year - 80 (LE default).
- **CEEDAYS separators**: literal characters in the picture string must match
  the date exactly (a mismatch returns 2508 "Datevalue error", a missing one
  2507 "Insufficient"). This is an assumption; LE's exact handling is unverified.
- **Menu copybooks** (COADM02Y / COMEN02Y): the table slots past the VALUE data
  have no VALUE clause in COBOL; the layouts initialise them to spaces.
- **CSUTLDTC TstDate**: reproduced bug-for-bug — the original moves the whole
  variable-length string (2-byte binary length X'000A' + date) into the 10-byte
  field, so the message shows `\x00\x0A` + the first 8 date characters.
- **FILE STATUS 02 on READ** via a non-unique alternate key follows IBM
  Enterprise COBOL ('02' when more duplicates follow). GnuCOBOL's BDB handler
  returns '00' there; this is the one known difference in the golden test.
- **Collation**: KSDS keys are ordered by EBCDIC byte value by default (as on
  z/OS) even though data is stored in ASCII; pass `collation: 'ascii'` for
  GnuCOBOL ordering. CardDemo keys are numeric/uppercase so this rarely matters.
- **AIX duplicate order**: after loading (REPRO + BLDINDEX), duplicates are in
  prime-key order; records added later are appended (upgrade-set order).
- **CICS**: RESP2 is only set for a few conditions (NOTFND 80, ENDFILE 90,
  DUPREC 150); locking is per `CicsFileControl` instance (no cross-task
  contention / RLS); MASSINSERT, NUMREC, TOKEN, SYSID are not supported;
  WRITE via a PATH inserts into the base cluster (RIDFLD = the alternate key).
- **USRSEC** is converted CP037 -> ASCII at load time; the store holds ASCII.
  The export file keeps EBCDIC bytes (it has binary/packed fields).
- **Seed quirks are preserved, not normalized**: e.g. account 49 ZIP is
  `A000000000` in the ASCII seed but differs in the EBCDIC export.
- **Sequential files** are read fully into memory on OPEN INPUT; LINE writes keep
  trailing spaces unless `trimTrailing: true` (GnuCOBOL trims by default).
- **COBSWAIT** non-digit SYSIN characters contribute their low nibble mod 10.

## Adding an online program

The online runtime lives in `src/online/` (see `src/online/README.md`). To add a CICS program port:

1. Create the module under `src/online/<area>/<program>.ts` exporting an `OnlineProgram`:
   ```ts
   import { CarddemoCommarea, DFHAID, SymbolicMap, populateHeaderInfo, type CicsContext, type OnlineProgram } from '../framework/index.js';
   function run(ctx: CicsContext): void {
     const map = new SymbolicMap('CACTVWA', 'COACTVW');          // generated from app/bms + app/cpy-bms
     const commarea = CarddemoCommarea.fromDfhCommarea(ctx.commarea); // MOVE DFHCOMMAREA(1:EIBCALEN) ...
     if (ctx.eib.eibcalen === 0) { /* first entry */ }
     if (ctx.eib.eibaid === DFHAID.DFHPF3) ctx.xctl('COMEN01C', commarea.toBuffer());
     const r = ctx.track(ctx.files.read({ file: 'ACCTDAT', ridfld: '00000000001' }));  // r.resp / r.record
     populateHeaderInfo(map, { tranid: 'CAVW', pgmname: 'COACTVWC', now: ctx.now() });
     ctx.sendMap(map, { mapset: 'COACTVW', erase: true, cursor: true });
     ctx.return({ transid: 'CAVW', commarea: commarea.toBuffer() });
   }
   export const COACTVWC: OnlineProgram = { program: 'COACTVWC', transid: 'CAVW', run };
   ```
2. Register it with **one line** in your area's file (no core file changes):
   - Session 7 (account/card): `src/online/areas/account-card.ts` -> `ACCOUNT_CARD_PROGRAMS`
   - Session 8 (transactions/bill pay/reports): `src/online/areas/transaction.ts` -> `TRANSACTION_PROGRAMS`
   - Session 9 (user admin): `src/online/areas/user-admin.ts` -> `USER_ADMIN_PROGRAMS`

   e.g. add `import { COACTVWC } from '../account/coactvwc.js';` and put `COACTVWC,` in the array.
   The TRANSID defaults to the CSD table (`CSD_TRANSACTIONS`) if `transid` is omitted.
3. Menus route to it automatically (until registered, the program behaves as not installed).
   Test through `createCardDemoRuntime({ catalog, clock })` -> `openTerminal` / `startTransaction` / `sendInput`
   (see `test/online/helpers.ts`), and try it in a browser with `npm run online` (http://localhost:8080).

Conventions: XCTL/RETURN throw (code after them does not run), HANDLE CONDITION PGMIDERR = `try { ctx.xctl(...) } catch (e) { if (e instanceof CicsCondition) ... }`, HANDLE ABEND = `ctx.abendHandler = ...`. Keep money in `Decimal`; use `numval`/`numvalC`/`formatEdited` from the framework helpers.
