# Record layouts used by the posting cycle

Every table below is generated by `python3 tests/golden/docs_numbers.py --layouts`
from `tests/golden/layouts.py`, which parses the copybooks under `app/cpy/`
(and, for the reject trailer, the working-storage lines of
`app/cbl/CBTRN02C.cbl`) at import time.  Offsets are 0-based byte positions
within the record; lengths are bytes; "Defined at" is the `path:line` of the
`PIC` clause the field comes from.  `selftest.sh` fails if this file no longer
matches what the parser produces.

Conventions (GnuCOBOL `-fsign=EBCDIC`, matching the repository's sample data):
signed zoned decimals carry the sign as a trailing overpunch on the last digit
(`{`=+0 `A`..`I`=+1..+9, `}`=-0 `J`..`R`=-1..-9); implied decimals are not
stored.  The comparator prints both the decoded value and the raw bytes when a
signed field differs.

Sort order of the dumped indexed files (`GSIDXUTL DUMP`): ascending primary key,
i.e. `TRAN-ID` for `TRANSACT`, `ACCT-ID` for `ACCTFILE`, `TRAN-CAT-KEY`
(`TRANCAT-ACCT-ID` + `TRANCAT-TYPE-CD` + `TRANCAT-CD`, `app/cpy/CVTRA01Y.cpy:5-8`)
for `TCATBALF`.  `DALYREJS` is sequential and is kept in write order.

## Notes

* `DALYREJS` has no copybook of its own.  `REJECT-RECORD` is `X(350)` +
  `X(80)` (`app/cbl/CBTRN02C.cbl:176-178`); the program fills the first 350
  bytes from `DALYTRAN-RECORD` (`:447`) and the trailer from
  `WS-VALIDATION-TRAILER` (`:448`), whose two fields are at `:181-182`.  The
  harness therefore models the reject record as the 14 `DALYTRAN` fields
  followed by `WS-VALIDATION-FAIL-REASON` and `WS-VALIDATION-FAIL-REASON-DESC`.
* `TRANSACT` (`CVTRA05Y`) and `DALYTRAN` (`CVTRA06Y`) have identical shapes;
  the program moves the fields one by one (`:425-436`) and stamps
  `TRAN-PROC-TS` (`:438`).
* `ACCT-EXPIRAION-DATE` is spelled as in the copybook (`app/cpy/CVACT01Y.cpy`).
